# أبو هاشم للحوم والألبان والأجبان

متجر عربي RTL خفيف. الموقع نفسه Static، والمنتجات محفوظة داخل GitHub، وبوتان منفصلان في Telegram.

## البنية النهائية

1. **الموقع:** Static من ملفات المستودع.
2. **المنتجات:** `data/products.json`.
3. **بوت الإدارة والنشر:** `bot-worker/`
   - إضافة المنتج
   - تعديل المنتج
   - إخفاء/إظهار المنتج
   - حذف المنتج
   - عرض المنتجات
   - كل تعديل يعمل Commit مباشر على GitHub.
4. **بوت استقبال الطلبات:** `order-worker/`
   - الموقع يرسل الطلب إلى Worker.
   - Worker يتحقق من المنتجات والأسعار.
   - Worker يرسل الطلب إلى بوت Telegram المخصص للطلبات.
5. **قاعدة البيانات:** غير مستخدمة، حتى يبقى المشروع بسيطاً وقليل الأعطال.
6. **رصيد السلة:** محفوظ محلياً في جهاز الزبون.
7. **الدفع:** غير موجود؛ الطلب للتواصل والتأكيد مع المحل.

## المنتجات

الملف:

`data/products.json`

الحقول:

- `id` رقم المنتج
- `n` اسم المنتج
- `p` السعر بالدينار العراقي
- `c` التصنيف
- `e` الإيموجي
- `active` إذا كانت `false` يختفي المنتج من الموقع ولا يقبل بوت الطلبات طلبه.

## بوت الإدارة والنشر

المجلد:

`bot-worker/`

الأوامر:

`/add الاسم | السعر | التصنيف | الإيموجي`

`/edit رقم | الاسم | السعر | التصنيف | الإيموجي`

`/hide رقم`

`/show رقم`

`/delete رقم`

`/list`

`/help`

الأسرار المطلوبة في Cloudflare Worker:

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_WEBHOOK_SECRET`
- `ADMIN_CHAT_ID`
- `GITHUB_TOKEN`

لا تضع أي Token داخل المستودع.

## بوت استقبال الطلبات

المجلد:

`order-worker/`

الأسرار المطلوبة:

- `TELEGRAM_BOT_TOKEN`
- `ORDERS_CHAT_ID`

بعد نشر Worker، ضع رابطه في:

`data/store.json`

داخل:

`orderApiUrl`

مثال:

`"orderApiUrl": "https://اسم-worker.اسم-حسابك.workers.dev"`

## تشغيل الموقع

المشروع مصمم للعمل كـ GitHub Pages أو أي Static Hosting/CDN.

لا يحتاج الموقع نفسه إلى Node.js أو قاعدة بيانات.

تم استخدام مسارات نسبية للملفات حتى يعمل الموقع أيضاً عندما يكون عنوان GitHub Pages على شكل:

`https://USERNAME.github.io/abu_hashim_stor/`

## سير الطلب

الزبون:

الموقع ← السلة ← بيانات التوصيل ← إرسال

ثم:

الموقع ← **Order Worker** ← **بوت استقبال الطلبات** ← المحل

## الاعتمادية

الموقع لا يعتمد على سيرفر دائم ولا قاعدة بيانات. إذا توقف Worker، الموقع يبقى قابلاً للعرض، لكن إرسال الطلبات يتوقف إلى أن يعود Worker للعمل.
